# Task4 思考题

## 1. Make 和 build.sh 的区别
build.sh 脚本从头到尾依次执行全部gcc命令，每次运行都会完整编译所有源码，不会检查文件是否改动。
Make 的优势：
- 增量编译：检查文件修改时间，**只编译改动过的文件以及依赖它的文件**，未改动文件不会重复编译；
- 自动管理.c与.h头文件之间的依赖；
- 支持多目标，例如 make clean，一键删除编译产物。
shell脚本没有依赖判断，每次都完整重编译，项目越大速度越慢。

## 2. CMake 不是编译器
CMake本身**不是编译器**。
执行`cmake --build build`时，CMake调用make作为底层构建工具，**真正将C源代码编译成机器码的是gcc**。
CMake只负责读取CMakeLists.txt，生成Makefile，管理构建流程，本身不做代码编译。

## 3. 只修改一个.c文件，不全部重编
一次性重编译50个文件会浪费大量时间。
没有修改的源码对应的目标文件`.o`不需要重新生成，只编译改动的文件，再链接全部目标文件，大幅节约编译时间，提升开发效率。
